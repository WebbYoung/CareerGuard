# DeepSeek接入与验证

按用户明确请求接入官方DeepSeek。模型：`deepseek-flash`；服务地址：`https://api.deepseek.com`。

## 配置

本机 `.env` 设置 `LLM_PROVIDER=deepseek`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_API_KEY`。本文件及源码示例不包含真实密钥，交付压缩包排除 `.env`。已有OCR目录配置保留。

也可选择 `LLM_PROVIDER=ollama` 使用原有本机模式。API请求不能修改供应商、密钥、地址或模型名。

## 数据与连接边界

- 本地OCR处理原始文件，完整简历不发送到DeepSeek。
- 云端只发送脱敏结构化风险证据、岗位技能/状态/来源编号与内置知识条目；剔除简历原始行、JD原文片段、未知要求全文、原始文件和凭据字段，未知要求仅保留数量。各字符串独立脱敏，保持JSON结构。
- 只允许官方HTTPS根地址或 `/v1`。实际主机固定为 `api.deepseek.com`，拒绝其他协议、主机、端口、路径和重定向；不配置搜索、抓取或工具能力。
- 密钥只在后端Authorization头使用，不下发浏览器、不写入日志或源码包。上游错误正文不回显。
- 保留注入拦截、JSON结构/长度、证据ID和谨慎措辞校验。LLM只补充解释，不改写规则分或关键词覆盖率。
- 页面显示“DeepSeek云端”和数据流向。云端服务自身的数据政策不由本地内存清空功能控制，不宣称所有分析均完全离线。

## 已验证

官方模型列表请求200且列出所需模型。使用匿名合成证据的真实风险解读、职业建议均成功，返回内容通过格式/证据引用校验。直接调用用时约2.37秒、3.08秒，仅代表本机本次样例。

当前57项自动测试覆盖既有功能及24项DeepSeek协议用例，含职业报告到云端载荷的原文剔除回归，以及空白、截断、工具调用、超长响应测试。模型协议测试使用虚构凭据和替身；另有独立真实调用验证，不把替身当作模型实测。

本地HTTP实测完成PaddleOCR招聘截图→风险100分→DeepSeek建议，以及基础简历/JD→38%覆盖率、4周计划→DeepSeek建议。会话状态不含凭据，注入测试仍拦截；独立合成测试会话已清空。独立代码复核确认云端原文剔除边界，57项测试通过。

## 演示

刷新平台后，工作台显示DeepSeek云端可用。重新分析招聘材料或生成职业报告，右侧AI面板应显示“DeepSeek云端”及有证据编号的建议。

密钥错误、余额不足、限流、网络超时或不合格输出会明确降级，已有规则与检索结果仍可查看。首次配置或改密钥后需重启后端。
