# AI 工作区配置与验收

本次新增功能的真实对话、Embedding与图片服务尚未联调；依照要求，配置前只做网络隔离的模拟测试。保存配置、打开页面或启动服务不会探测模型，也不会自动构建向量。

## 功能入口

- `/app` → AI简历生成：新建简历 → 逐项对话收集真实经历 → 编辑草稿 → AI整理成简历 → 对照依据并应用 → 下载Word。AI建议稿独立保存，不能直接替换原始事实。
- 简历内“职业证件照”：上传本人PNG/JPEG照片 → 一寸/二寸/小二寸、白/蓝/红背景 → 授权本次发送图片模型 → 生成并附入Word。原自拍仅在内存处理，生成图按账号加密保存。
- 小安机器人：点击开启对话，推荐问题提供快捷入口；操作说明不调用模型。查询个人档案需另行勾选，只返回当前账号的脱敏摘要。填写建议显示预览，确认后填入个人中心，仍需用户点击保存。
- `/company/register`：注册企业管理员并上传营业执照；格式/校验位/OCR检查后由平台人工审核。`/company`只管理该企业的岗位。企业材料通过且岗位内容审核通过后，岗位进入前台推荐列表；企业被退回时相关岗位停止公开。
- `/admin` → 企业材料审核、AI模型与知识库：分别配置对话、Embedding和图片模型，管理知识条目并手动构建索引。

## 模型配置

对话支持OpenAI兼容Chat Completions、Anthropic Messages与Ollama；供应商与模型名可自行填写。工具调用会按协议转换。Embedding支持OpenAI兼容及Ollama。证件照要求支持OpenAI兼容 `/images/edits`、返回base64图片的编辑模型，纯文本模型不能处理照片。

密钥加密保存、不回显，留空保留旧密钥。常见官方服务已设允许主机列表；自定义公网网关在服务器环境变量 `MODEL_ALLOWED_HOSTS` 追加主机，HTTPS443，无重定向、私网DNS或任意链接抓取。Ollama仅使用固定回环服务。前端不会自动请求材料中的链接。

配置Embedding后添加TXT/Markdown或直接录入知识正文，再主动点击“手动构建向量索引”。向量、文档分块、模型指纹与版本保存于SQLite；更换模型、维度或修改知识后需重建。没有完整可用索引时明确降级为关键词检索。知识库为管理员维护的共享职业资料，请勿放入个人简历；简历原文不会作为知识库自动入库。

## 人工联调顺序（配置后执行）

1. 保存对话模型；用非敏感职业问题验证文字回复及工具调用。
2. 保存Embedding配置，导入少量公开职业知识并手动构建；检索时确认引用和“向量检索”状态，更换模型后确认重建提示。
3. 用合成经历完成简历对话和润色，人工对照事实，下载DOCX查看字段、段落和引用说明；不应凭空产生履历、数字或证书。
4. 配置图片编辑模型，再使用已授权自拍验证三种背景与尺寸。生成可能改变细节，正式证件以受理要求为准。
5. 用两个不同企业测试岗位归属；未审核企业不能发布，未审核岗位不得公开，退回企业后岗位不可检索。
6. 小安查询档案、岗位与知识；拒绝未授权档案查询及未知工具；填写建议只修改前台草稿，不自动提交。
7. 清空个人资料后，简历/照片/聊天立即消失；未完成请求不得重新写回。已发布岗位、点评和企业审核资料按原产品规则保留。

## 数据与安全边界

简历草稿、对话、处理后证件照、企业执照和模型密钥使用服务端密钥加密；SQLite使用账号外键和归属检查。原始简历上传与自拍不写文件。营业执照为审核需要按授权加密保存在数据库，企业页面已说明。备份应同时妥善管理数据库与加密密钥。

会话使用原有HttpOnly Cookie、CSRF与账号数据代数；迟到回复通过版本与删除代数检查阻止写回。小安最多3轮、6次白名单工具调用，不提供任意SQL、网页访问、代码执行或管理员配置工具。模型、岗位和知识条目均视为不可信内容，前端以文本渲染。

服务保持单进程运行方式；上线时使用HTTPS反向代理并按实际域名设置可信主机。企业材料审核不等同政府认证，职业建议不保证录取或收益。
