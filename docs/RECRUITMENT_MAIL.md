# 后台分页与招聘沟通闭环

## 页面入口

网站管理员：`/admin?page=overview`、`users`、`jobs`、`reviews`、`companies`、`models`、`knowledge`、`security`、`mail`。左侧导航切换独立页面，仅显示当前模块，支持直达、前进后退并保留未提交表单。网页初始化期间隐藏待重组的旧片段，避免长页面闪现。

企业管理员：`/company/overview`、`/company/jobs`、`/company/publish`、`/company/candidates`、`/company/mail`。侧栏采用与前台相同的玻璃图标，卡片光晕、边缘流光、背景粒子/流星和强度开关均已接入。公司只能管理自己的岗位。

普通用户：前台岗位“一键面试”，个人中心“我的岗位投递”，新增“站内邮件”。原账号卡片的头像、昵称、城市和简介继续保留；修复脚本迟到时首次加载仍显示用户名的问题。

## 求职者到企业的流程

1. 企业材料通过后发布岗位，岗位内容仍需平台审核。
2. 求职者在岗位推荐点“一键面试”。公司岗位会要求选择个人档案或简历工作室草稿并明确授权共享；个人练习岗位不向公司投递。
3. 服务器保存加密的履历快照，自动填写面试岗位与JD。发送岗位信息给AI仍需在面试页另行勾选授权，本轮并未调用真实模型。
4. 真正创建面试时由服务器关联申请与面试记录；只是点击按钮或投递不会虚增面试人数。企业按岗位查看有效投递、授权简历与去重面试人数，看不到训练对话、评分、声音或镜头。
5. 企业从授权候选卡点“联系意向”，收件人由服务器确认。求职者在站内邮件中阅读和回复，未读数字由长轮询同步。
6. 求职者可以撤回授权；服务端立即清空共享快照并停止企业继续联系。撤回后以未授权岗位面试的方式重新投递，不会恢复旧的面试统计。删除个人资料也会撤回所有投递快照。

## 站内邮件与外部邮箱

站内消息独立可用，无需SMTP。消息正文加密存储，企业只能联系有效投递本企业岗位并授权的用户；普通用户回复已有会话；管理员可在用户管理点“发送通知”。默认不会外发邮件。

需要外发时，管理员在“邮件与通知”配置SMTP（465 SSL或587 STARTTLS）；密码加密保存、不回显，保存不探测。用户在站内邮件关联邮箱，主动获取验证码并验证，同时勾选接收职业联系邮件；企业或管理员仍需手动勾选本次同步至邮箱。

只支持常见官方SMTP主机及环境变量`SMTP_ALLOWED_HOSTS`明确允许的主机。发送时校验全部DNS地址为公网并绑定连接IP，TLS仍校验证书和主机名。外部邮件失败会明确标注，已送达的站内消息仍保留。验证码响应不会返回验证码；输入错误、发信频率和账号权限均有限制。

长轮询最长20秒，每0.5秒检查账号禁用和数据代次，使用AbortController停止旧客户端请求；新消息推送未读状态，页面给出提示。读邮件使用POST+CSRF改变已读状态，GET只读取。

删除个人资料会清空头像/昵称/简介、已关联邮箱和学习资料，并撤回履历快照；已发布岗位、点评、站内沟通和企业审核材料保留。界面明确说明保留范围。

## 验证记录

- 192项Python离线测试通过，包含招聘/消息权限、撤回、原始草稿/AI建议分离、真正面试关联、并发撤回、邮箱验证、SMTP安全传输替身、审计和客户端旧响应竞态。
- 58项Node测试通过，包含后台直达/切页/前后退/草稿保留、企业图标与路由、自动面试准备、AI授权重置、头像装饰与脚本迟到。
- 所有静态JavaScript语法检查通过。
- 浏览器使用独立测试数据库和合成账号验证：后台独立模型/知识库/SMTP页面；岗位自动填入及授权；企业查看合成履历、发送站内意向邀请；求职者未读提醒、阅读、回复。390px后台无横向溢出。
- 未调用真实AI/Embedding、未向外部邮箱发送邮件。测试账号及数据库不打入交付源码包。
